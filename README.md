# Stackboard

macOS-приложение в строке меню: скриншоты с аннотациями и история буфера обмена.

## Требования

- macOS 13.5 или новее.
- Apple Silicon или Intel: релизный архив содержит Universal-приложение `arm64 + x86_64`.
- Разрешение Screen Recording для создания скриншотов.

Homebrew объявляет минимум только на уровне основной версии macOS: cask использует `depends_on macos: :ventura`. Точный минимум **13.5** остаётся в `Info.plist` приложения и проверяется macOS при запуске; одной зависимости cask недостаточно для проверки версии 13.x.

## Установка через Homebrew

```sh
brew install --cask 0x0faced/stackboard/stackboard
open /Applications/Stackboard.app
```

В Homebrew 7 сторонний cask может потребовать явного доверия. Если установка сообщает об untrusted tap/cask, разрешите именно этот cask и повторите установку:

```sh
brew trust --cask 0x0faced/stackboard/stackboard
brew install --cask 0x0faced/stackboard/stackboard
```

Это доверие к Ruby-конфигурации Homebrew, а не обход Gatekeeper. В более старом Homebrew команды `trust` может не быть; она нужна только при соответствующем сообщении.

Обновление: сначала закройте Stackboard через его меню, сохранив нужные правки в редакторах.

```sh
brew update
brew upgrade --cask 0x0faced/stackboard/stackboard
open /Applications/Stackboard.app
```

Homebrew не обновит уже запущенный процесс: после замены приложения нужен повторный запуск.

Удаление приложения:

```sh
brew uninstall --cask 0x0faced/stackboard/stackboard
```

Cask устанавливает только `.app`: обычное удаление не должно удалять историю и настройки. История хранится в `~/Library/Application Support/Stackboard`, настройки — в домене `dev.0xfaced.Stackboard`.

## Установка без Homebrew

1. Откройте [GitHub Releases](https://github.com/0x0FACED/stackboard/releases) и скачайте `Stackboard.zip` и `SHA256SUMS` одной версии.
2. В папке загрузки проверьте архив:

   ```sh
   shasum -a 256 -c SHA256SUMS
   ```

3. Распакуйте ZIP. Перед заменой существующего приложения закройте Stackboard и сохраните нужные правки.
4. Перенесите `Stackboard.app` в `/Applications` и откройте его.

SHA-256 подтверждает целостность скачанного файла, но не является сертификатом доверия к издателю.

### Разрешение запуска и записи экрана

Релизы подписаны **ad-hoc**, без Developer ID и notarization. Платный Apple Developer Program для этого процесса не нужен, но подпись не делает приложение доверенным для Gatekeeper.

Если macOS блокирует запуск, после попытки открытия проверьте **Системные настройки → Конфиденциальность и безопасность** и используйте **«Всё равно открыть»**, если система предлагает этот пункт и вы доверяете скачанному приложению. Корпоративная политика может не разрешать такое открытие. Не отключайте Gatekeeper глобально.

При первом скриншоте разрешите Stackboard запись экрана в том же разделе настроек и перезапустите приложение, если macOS требует этого. После обновления ad-hoc-приложения система может запросить разрешение повторно. Homebrew не выдаёт это разрешение автоматически.

## Сборка и упаковка локально

Нужны полный Xcode 26.4 или совместимая более новая версия и Python 3. Активный Xcode выбирается через `xcode-select` или `DEVELOPER_DIR`.

```sh
bash scripts/package-release.sh 1.0.1
```

Скрипт не использует сертификаты и не меняет локальные настройки подписи Xcode-проекта. Он переопределяет версию, архитектуры и подпись только для данной сборки.

Результаты находятся в `dist/1.0.1/`:

- `Stackboard.app` — проверенное Universal-приложение;
- `Stackboard.zip` — архив для установки;
- `SHA256SUMS` — SHA-256 архива;
- `release.json` — фактические версия, build number, минимальная macOS, архитектуры и SHA-256 для автоматизации.

По умолчанию build number равен `1`. Можно задать положительное целое число и другую папку вывода:

```sh
BUILD_NUMBER=17 bash scripts/package-release.sh v1.0.1 /tmp/stackboard-package
```

Допустимы только стабильные версии `X.Y.Z`, с необязательным префиксом `v`. Папка сборки должна отсутствовать или быть пустой: скрипт не перезаписывает существующие результаты. Из папки другого проекта запускать его можно — пути к исходникам разрешаются относительно самого скрипта.

Повторная проверка опубликованного пакета без сборки и изменения ZIP:

```sh
bash scripts/package-release.sh --verify-existing 1.0.1 dist/1.0.1
```

В папке должны быть `Stackboard.zip` и `SHA256SUMS` одной версии. Если `.app` и `release.json` отсутствуют, они создаются из проверенного архива; существующие должны совпадать с ним. Чужие файлы и несовпадающие результаты не заменяются.

Проверяются checksum, пути и symlinks до распаковки, версия и идентификатор приложения, архитектуры всех упакованных Mach-O, подписи обеих архитектур и отсутствие отладочного `get-task-allow`.

## Бесплатный GitHub Actions workflow

Все jobs используют стандартные runners и запускаются только для **публичных** репозиториев. Платные larger runners, хранение Actions artifacts и Actions cache не используются. Приватизация репозитория отключит эти jobs вместо перехода на платную сборку.

### CI

`.github/workflows/ci.yml` запускается на push в `main`, pull request и вручную:

- проверяет workflow через закреплённый `actionlint`;
- проверяет shell-синтаксис и поведенческие тесты release-инструментов;
- собирает Universal-пакет и повторно проверяет готовый ZIP.

macOS job использует `macos-26` и Xcode **26.4.1**, установленный в официальном образе runner. Если GitHub удалит эту версию Xcode из образа, обновите `DEVELOPER_DIR` в обоих workflow и проверьте новую сборку. Автоматического перехода на другой компилятор нет.

### Однократная настройка Homebrew-токена

Создайте fine-grained Personal Access Token в настройках аккаунта GitHub:

**Settings → Developer settings → Personal access tokens → Fine-grained tokens.**

- Resource owner: `0x0FACED`.
- Repository access: только `homebrew-stackboard`.
- Repository permission: **Contents — Read and write**.
- Выберите срок действия; истёкший токен нужно заменить.

В основном репозитории **`0x0FACED/stackboard`** откройте:

**Settings → Secrets and variables → Actions → New repository secret.**

Сохраните токен под именем **`HOMEBREW_TAP_TOKEN`**. Не помещайте его в код, README, вывод команд или чат.

Встроенный `GITHUB_TOKEN` публикует Release в основном репозитории. Отдельный токен нужен только для второго репозитория. Workflow делает прямой push в `main` tap: его правила защиты ветки должны допускать такую запись выбранной учётной записью. Права администратора и доступ ко всем репозиториям токену не нужны.

### Выпуск версии

Сначала закоммитьте исправления, release-инструменты и workflow. Тег должен указывать именно на этот коммит: незакоммиченные изменения в релиз не попадут.

```sh
git push origin main
git tag v1.0.1
git push origin v1.0.1
```

`.github/workflows/release.yml`:

1. Проверяет стабильный тег и наличие секрета, затем получает исходники этого тега.
2. Для нового релиза собирает и проверяет ZIP. Версия берётся из тега, build number — из номера запуска Actions.
3. Подготавливает изменение `Casks/stackboard.rb` и проверяет, что оно не понижает текущую версию tap.
4. Создаёт/обновляет draft, загружает ZIP и checksum, затем публикует Release.
5. Коммитит и отправляет в tap новые `version`, `sha256` и символ основной версии macOS из фактического `Info.plist` (например, `13.5` → `:ventura`). Minor/patch-минимум сохраняется в самом приложении.

В Release публикуются только `Stackboard.zip` и `SHA256SUMS`. `release.json` служит локальной автоматизации. Платные подписи, notarization и секреты Apple не используются.

### Повторный запуск и ошибки

- Если публикация остановилась на draft, повторный запуск пересобирает пакет и заменяет только **неопубликованные** assets draft.
- Если Release уже опубликован, workflow скачивает и проверяет его существующие ZIP/checksum. Он не пересобирает, не переподписывает и не перезаписывает опубликованные файлы.
- Если публикация прошла, а push в tap не удался, исправьте токен или конфликт и повторите job через **Actions → Release → Re-run failed jobs**, либо запустите **Run workflow**, указав тот же существующий тег.
- У старых ручных релизов, например начального `v1.0.0`, нет обязательного `SHA256SUMS` и новых скриптов в tagged source. Первый автоматический релиз должен иметь новый тег на коммите с этой инфраструктурой.
- Понижение версии tap и замена SHA-256 уже известной ему версии запрещены. Чтобы выпустить изменённое приложение, создайте **новую версию**, а не двигайте старый тег.
- Все release-запуски сериализованы. Не меняйте tap параллельно вручную; при конфликте push workflow завершится ошибкой, опубликованный ZIP останется неизменным.

## Проверка release-инструментов

```sh
bash -n scripts/package-release.sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
```

Тесты не выполняют сетевых запросов и не меняют установленный Homebrew tap. Основной положительный smoke — реальный запуск `package-release.sh` и `--verify-existing` на macOS, а не только тесты генерации metadata.
